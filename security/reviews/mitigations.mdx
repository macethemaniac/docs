---
title: "Mitigations"
description: "Controls Lotus uses to reduce execution and accounting risk."
---

Lotus reduces risk with layered controls.

No single control is enough. Execution safety depends on routeability, authorization, funding, submit, settlement, and accounting checks working together.

## Routeability controls

Lotus checks:

- Shared outcome core.
- Rule compatibility.
- Fresh quote availability.
- Venue market and outcome IDs.
- Venue capability status.
- Settlement support.

These checks prevent unsafe venue combinations.

## Authorization controls

Lotus uses:

- Execution scope tokens.
- Signature request hashes.
- Single-use order scope.
- Idempotent place and signature handling.
- Time-bound approvals.

These controls reduce replay and rerouting risk.

## Execution controls

Lotus enforces:

- Slippage tolerance.
- Order policy.
- Venue readiness.
- Funding readiness.
- Submit-path support.
- Fail-closed behavior.

If a route becomes unsafe before submit, Lotus should not execute it.

## Accounting controls

Lotus records:

- Per-leg fills.
- Settlement verification.
- Position updates.
- Balance updates.
- Surplus and fee calculation versions.
- Receipt state.

These controls prevent ghost fills, missing positions, and duplicate revenue entries.

## Information safety

Lotus should explain controls without exposing sensitive material.

User-facing docs, receipts, and logs should not expose:

- Production credentials.
- Provider credentials.
- Raw signed payloads.
- Raw provider payloads.
- Session tokens.

<Warning>
  Transparency should make the security model understandable without exposing sensitive execution material.
</Warning>
