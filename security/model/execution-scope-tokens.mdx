---
title: "Execution scope tokens"
description: "How Lotus narrows execution authority to one route."
---

Execution scope tokens, or ESTs, bind user authorization to a specific route.

The user approval should authorize exactly what was shown, not an open-ended class of future routes.

## What an EST binds

An EST can bind:

- User.
- Market.
- Outcome.
- Side.
- Amount.
- Route type.
- Venue set.
- Price band.
- Slippage tolerance.
- Order policy.
- Expiry.

If one of these changes, Lotus should create a new scope instead of reusing the old one.

## Why ESTs matter

ESTs reduce the gap between quote and execution.

They prevent the backend from using a signature for a route the user did not approve. They also make retries safer because the backend can return the current order state when the same scoped intent appears again.

## Public disclosure boundary

Safe to disclose:

- What an EST binds.
- Why ESTs are single-use.
- Which states require a signature.
- How the user flow should feel.

Do not disclose:

- Raw EST signing secrets.
- Private token construction material.
- Internal key rotation details.
- Raw signed payloads.
