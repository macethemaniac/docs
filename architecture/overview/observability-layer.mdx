---
title: "Observability layer"
description: "How Lotus records execution evidence safely."
---

The observability layer records enough evidence to explain and audit Lotus behavior.

It should protect sensitive credentials and user data while still making execution outcomes understandable.

## What Lotus observes

Lotus records:

- Route decision inputs and outputs.
- Quote freshness and expiry.
- Venue readiness summaries.
- Execution state transitions.
- Settlement verification results.
- Funding readiness changes.
- Surplus and fee calculation versions.
- Error codes and blocker categories.

These records help Lotus explain why a route was selected, blocked, filled, or failed.

## What Lotus redacts

Logs and traces should not include:

- API keys.
- Private keys.
- Webhook signing secrets.
- Raw signed payloads.
- Database URLs.
- Provider auth headers.
- User session tokens.
- Wallet recovery material.

Where possible, logs should store stable references and hashes instead of raw sensitive values.

## Audit records

Audit records should be reproducible.

For an execution, Lotus should be able to reconstruct:

- The route shown to the user.
- The execution scope.
- The venue legs used.
- The verified fills.
- The final accounting outcome.
- The fee policy version.

This supports transparency while keeping sensitive implementation details out of user-facing surfaces.

<Warning>
  Observability should help explain execution, not expose credentials or sensitive user data.
</Warning>
