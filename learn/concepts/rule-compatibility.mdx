---
title: "Rule compatibility"
description: "How Lotus tests resolution equivalence."
---

Rule compatibility is the test Lotus uses to decide whether venue markets can safely share a route.

Two markets can have similar titles and still resolve differently. Lotus checks the actual venue-sourced resolution rules before treating them as the same routeable outcome.

## What Lotus compares

Lotus checks:

- Resolution rule text.
- Resolution source.
- Expiration and resolution timing.
- Outcome schema.
- Edge cases.
- Venue-specific settlement behavior.
- Whether the same real-world event is being measured.

## Compatible, partial, incompatible

Lotus can classify rule relationships as:

- `compatible`: safe to route within the shared outcome core.
- `partially compatible`: useful for display or review, but not automatically safe for all route shapes.
- `incompatible`: not routeable together.

## Example

Two venues may both ask whether a token reaches a price by a date.

They may still differ on:

- Which exchange price is used.
- Whether intraday wicks count.
- Which timezone defines the deadline.
- What happens if the data source is unavailable.

Those differences can change settlement. Lotus must treat them as execution-critical.

## Why title matching is not enough

Titles are noisy. Rules are authority.

Lotus should use venue-sourced rules, source URLs, slugs, dates, and outcome metadata to justify a canonical match. If the metadata is missing or placeholder quality, the market should not be promoted into a routeable execution lane.
