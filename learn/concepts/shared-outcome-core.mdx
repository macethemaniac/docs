---
title: "Shared outcome core"
description: "The routeable overlap between venue markets."
---

The shared outcome core is the part of two or more venue markets that resolves the same way.

Lotus only routes inside that shared core.

![Canonical market flow](/images/learn/canonical-market-flow.svg)

## Why shared core matters

Prediction markets can look similar while including different outcome sets.

For example, one venue may list a broad event winner market, while another venue lists only a specific candidate or a differently scoped condition. Routing across the full title would be unsafe. Routing across the shared outcome core may still be safe.

## What can be inside the core

The shared core can include:

- The same binary Yes/No outcome.
- The same named candidate in a multi-outcome market.
- The same threshold and deadline.
- The same resolution source.
- The same settlement interpretation.

## What is outside the core

Lotus should exclude:

- Venue-only tail outcomes.
- Outcomes with missing token IDs.
- Markets with different resolution sources.
- Markets with different cutoff times.
- Ambiguous or placeholder rules.

## How this affects routing

The router can only use venue legs that share the routeable core.

If a market has five outcomes but only three are mapped across venues, Lotus should route only the mapped outcomes. The rest can remain visible for discovery, but they are not automatically executable across venues.
