---
title: "RFQ layer"
description: "Request-for-quote against connected LPs."
---

The RFQ layer lets Lotus ask eligible liquidity providers for executable quotes on canonical market demand.

It gives market makers a structured way to supply liquidity without requiring users to manually compare LP quotes, venue books, and route risk.

![RFQ flow](/images/learn/rfq-flow.svg)

## When Lotus uses RFQ

Lotus can use RFQs when:

- Venue orderbook depth is thin.
- A market maker can improve the book price.
- A larger order would move the venue book too much.
- A pair or tri route needs additional liquidity.
- The RFQ quote can pass the same routeability checks as a venue quote.

RFQ liquidity competes with venue orderbooks. It does not bypass route safety.

## How the flow works

1. A user creates trading demand on a canonical market.
2. Lotus opens an RFQ session for eligible LPs.
3. LPs submit authenticated quotes with price, quantity, fee, and expiry.
4. Lotus validates quote identity, freshness, idempotency, and resolution lane compatibility.
5. The router compares LP quotes against venue books and other candidates.
6. The selected route can be accepted and executed through the normal execution layer.

## What LPs submit

An LP quote includes:

- RFQ session ID.
- LP quote ID.
- Price.
- Quantity.
- Fee in basis points.
- Expiration time.
- Optional payload metadata.

Lotus signs and validates the LP request at the API edge. A quote is accepted into the RFQ session only if the LP identity, nonce, timestamp, session state, and quote ID checks pass.

## Why RFQ helps users

RFQ liquidity can improve execution when public orderbooks are shallow or fragmented.

The user does not need to know whether the winning route came from one venue, multiple venues, or an LP quote. Lotus can show the route summary and execute through the same backend-owned order flow.

## Why RFQ helps LPs

LPs get structured, canonical flow instead of integrating separately with every frontend or venue.

They can quote the markets they understand, compete on execution quality, and receive fills when their quote improves the user's route.

## Safety rules

RFQ quotes are not automatically executable.

Lotus still checks:

- Quote expiry.
- Routeability.
- Rule compatibility.
- Resolution lane eligibility.
- User slippage tolerance.
- Execution scope.
- Settlement and accounting safety.

<Note>
  RFQ is an additional liquidity source. It does not weaken Lotus's fail-closed execution model.
</Note>
