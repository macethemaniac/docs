---
title: "Funding readiness"
description: "How Lotus decides whether a venue can be used for a trade."
---

Funding readiness answers one question: can this venue leg be executed right now?

Lotus checks readiness before preview, before place, and before submit.

![Funding readiness flow](/images/learn/funding-readiness-flow.svg)

## Readiness for buys

For buy routes, Lotus checks:

- Available user funding.
- Venue-ready cash.
- Required venue activation.
- Spending approvals where needed.
- Venue submit support.
- Minimum and maximum order constraints.

If any required step is missing, the order should not submit.

## Readiness for sells

For sell routes, Lotus checks:

- Verified position size.
- Sellable shares.
- Venue outcome token ID.
- Venue account readiness.
- Any signer or approval needed for the sell.

Selling is stricter because Lotus must prove the user owns the exact sellable outcome before it builds the order.

## Readiness states

Readiness can be:

- Ready to trade.
- Waiting for venue confirmation.
- Needs activation.
- Needs deposit.
- Blocked by missing venue metadata.
- Blocked by unsupported execution path.

The user interface should turn these into simple actions and show deeper reasons only when they help the user resolve the issue.

## Common mistakes

- Do not submit while a venue is still propagating activation.
- Do not show a route as ready if the sell token ID is missing.
- Do not treat one ready venue as proof that every route leg is ready.
- Do not hide an actionable funding requirement from the user.

<Warning>
  Funding readiness can change between preview and submit. Lotus must recheck it.
</Warning>
